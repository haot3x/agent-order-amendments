# ERC-8412 criteria supersession experiment

Author: Ted (@haot3x)

This test-only adapter connects the ERC-8448 amendment experiment to the pinned,
unmodified ERC-8412 reference registry. It tests the distinction raised in the
[discussion](https://ethereum-magicians.org/t/erc-8412-preregistered-acceptance-criteria/29609/12):
author access to a registry must not become unilateral permission to change a
bilateral order's acceptance criteria.

## Authority and atomicity

The adapter is the criteria author. Its initial registration copies the terms
already funded by the buyer and activated by the provider. Anyone can trigger
that copy, but cannot choose its digest or metadata. There is no arbitrary
supersession entry point.

A criteria-changing amendment uses the existing signed ERC-8448 payload and
acceptance from **both** parties. After the normal current-state checks, a narrow
internal hook registers the successor inside the isolated application call.
Supplemental funding and the order revision then update in the same call. Any
failure rolls back the new registration, old record's `supersededBy`, token
movement, revision and amendment nonce. The coordination attempt still records
failure and cannot be replayed; retry requires fresh consent.

The default hook is empty, so the base profile, signatures and fixed vectors do
not change. This fixture fixes one required/non-waivable obligation, an immutable
verifier, a chain/contract/order task reference, and expiry equal to the signed
order deadline. It only handles criteria-changing amendments; the base contract
continues to support ordinary price-only changes.

## Documents and evidence

`acceptanceHash` is the Keccak-256 digest of the complete canonical JSON criteria
document, not an ABI hash or a digest of a human-readable summary. Tests construct
ASCII/safe-integer documents whose sorted serialization agrees with JCS, and
compare the registry fields with the committed document. The adapter does not
parse JSON on-chain: signers/verifiers must validate that correspondence before
consenting or attesting.

The local policy is **no automatic evidence carry-forward**. Each successor has
a new `registeredAt`. The O1 subset example rejects evidence bound to the old
registration and evidence captured before the successor's timestamp. Recaptured
evidence at or after that time may be eligible, subject to the remaining checks.

This is not a complete O1-O5 verifier, capture-time authentication, or a proof of
work quality. The example does not wire a registry verdict directly to payout;
settlement keeps the existing buyer-review policy. Initial registration must
also precede evidence collection; activating the order alone is not registration.
A final prior verdict blocks supersession, while `Indeterminate` permits it under
the upstream rules. Old records remain inspectable and cannot receive a new
attestation after supersession.

## Reproduce

```sh
npm ci --ignore-scripts
npm run test:criteria
npm test
```

The registry is pinned to `6ba1149f5c21f80135b79d47e5ca51b71bc33059` from
richard7463/ERCs, with its original CC0-1.0 SPDX header and an integrity check
before compilation. Both contracts compile locally with Solidity 0.8.37.

On 2 November 2026, all **89 tests** passed, including eight new registry/EVM
cases. Removing the supersession hook makes the atomic-success test fail; the
hook was restored before the full run. The fixed vectors remain unchanged and
the full local lifecycle demo passes. No public-chain deployment is included.
